За да може да работи проекта е необходимо да имате инсталирани PHPStorm, Docker и Postman (за генериране на заявки към базата с данни). 

За стартиране на проекта, моля да изпълните следните стъпки (за Windows):
1. Стартиране на Docker;

2. Копиране на url https://github.com/Vi1006/Warehouse-DB.git

3. Отваряне на терминала и изпълняване на следните команди:
	3.1 git clone -b warehouse https://github.com/Vi1006/Warehouse-DB.git - за сваляне на локално копие на проекта (клон warehouse).
	3.2 docker compose build 	- за инсталиране на Docker Images & Containers.
	3.3 docker compose up -d 	- за стартиране на Docker Containers в detached mode.
След тези стъпки проекта вече трябва да бъде стартиран. 

4. За преглед на проекта в PHPStorm:
	4.1 Отваряте PHPStorm
	4.2 File -> Open -> навигирате до директория където са се запазили git clone файловете. Името на папката е Warehouse-DB.
При успешно стартиране на проекта, в браузъра успешно следва да се зареди страницата http://localhost:8080/

5. Зареждане на данни в DB. В терминала изпълняваме командите:
	5.1 docker exec -it laravel /bin/bash 	- за влизане в контейнер Laravel в Docker;
	5.2 php artisan migrate:fresh --seed 	- за мигриране на базата с данни и импортиране на данни във всяка таблица (10 реда на таблица)
	
6. За визуализиране на DB в PHPStorm проекта
	6.1 Добавяме нова база с данни: Database -> бутон + -> Data source -> MariaDB (laravel)
	6.2 User: root / Password: password / Database: laravel
	
В терминала може да извикаме всичките създадени route за заявките с командата: php artisan route:list . Създадените завки са:
- Заявка get за всяка таблица.
- Заявка get(id) за всяка таблица - извиква съответното id от таблицата.
- Заявка post за таблици Addresses, Cities, Clients, Inventories и Orders. С заявката post добавяме нови редове в таблиците.
- Заявка put(id) за таблици Addresses, Cities, Clients, Orders. С тази заявка може да променяме съответния ред от таблицата.
- Заявка delete за таблици Addresses и Cities - за изтриване на редове по id от таблицата.

Повече информация за проекта:

Папка app/Http/Controlers - класове за всяка таблица съдържащи функции за get, getById, store, edit и delete:
	- функция index - с тази функция се изпълнява route заявката get. Тя връща информация в json формат за всички редове в съответната таблица. Освен да връща всички редове, в някои от контролерите, фунцкията може да върне и информация само за един ред при извикване по определени критерии. Например, в таблица Addresses може да се търсят адреси по име на градове, по id на града или по име на улица. В таблица Cities може да се търси конкретен град по име;	
	- фунцкия getById - изпълнява route заявката get(id). При зададено id фунцкията връща json формат информацията за съответното id;
 	- фунцкия store - изпълнява route заявката post. След изпълнение на заявката връща информация за добавения ред в json формат. Работи за контролерите:
  		- AddressesController - при въведени address и city_id запазва нов адрес в таблицата;
    		- CityController - при въведено име на града добавя нов ред в базата с данни. В случай, че не е въведено име или града вече съществува в таблицата, дава съответната грешка;
      		- ClientController - при въведени address_id, first_name, last_name, email и password запазва нов клиент в таблицата. В случай, че някое от полетата не е попълнено връща грешка, че полето липсва. В случай, че имейл адреса съществува в базата с данни също връща грешка. 
		- OrderController - при въведени order_status_id, client_id и quantity запазва нова поръчка в таблицата; В случай, че някое от полетата не е попълнено връща грешка, че полето липсва. При невалиден клиент, връща грешка. При невалидно подадено количество (числото трябва да е в интервала 1-100 и да е цяло число) също връща грешка.
  		- InventoryController - при въведени name и description запазва стоката в таблицата. Има проверка за полетата - при празни полета дата грешка. Ако го името съществува в базата данни също дава грешка;
    	- функция edit - изпълнява route заявката put. 
     		- AddressController - при извикване на ред от таблицата по id, позволява промяна на полетата street и city_id. При невалидни параметри дава грешка. 
       		- CityController - при извикване на ред от таблицата по id, позволява промяна на името на града. Ако името не съществува в базата с данни, дава грешка.
	 	- ClientController - при извикване на ред от таблицата по id, позволява промяна на полетата first_name, last_name, address_id и password. При невалидни полета дата грешка. При опит за промяна на друго поле също дава грешка.
   		- OrderController - при извикване на ред от таблицата по id, позволява промяна на полетата status, client_id и quantity. При невалидно id на поръчката дава грешка. При невалидни полета status, client_id или quantity също дава грешка. 
     	- функция delete - изпълнява route заявката delete:
      		- AddressController - при извикване на ред от таблицата по id, ако id-то е валидно изтрива съответния ред от таблицата. Ако id-то не е валидно връща грешка;
		- CityController - при извикване на ред от таблицата по id, ако id-то е валидно изтрива съответния ред от таблицата. Ако id-то не е валидно връща грешка.

I.2. Папка app/Models - класове за всяка таблица, който връща в json формат информация към всеки контролер;

II.1 Папка Database/Factories - класове с методи за дефиниране на базови таблици за DB;

II.2 Папка Database/Migrations - класове за изпълняване и изтриване на миграцията от Seeders в базата с данни;
		- с командата docker compose up - изпълнява миграцията на базата с данни;
	 	- с командата docker compose down - изтрива миграцията от базата с данни;
II.3 Папка Database/Seeders - съдържа функции за всяка таблица за генериране на данни в DB (до 10 реда на таблица);

III. Папка Routes/api.php - съдържа route фунцкии за изпълняване на всички заявки. Всеки route извиква команда от съответния Controller;
